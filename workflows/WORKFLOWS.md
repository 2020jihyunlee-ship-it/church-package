# 워크플로우 3본 — 명세 v1 (구현은 로드맵 3주차)

> 워크플로우 = 사건이 나면 저절로 도는 배관 (스킬은 사람이 부를 때 일하는 능력).
> 전부 로컬 파이썬 — 구동 시 AI 사용료 0. 자비스 스케줄러(cys schedule) 또는 OS 스케줄러에 등록.

## W1. 은혜 회수 (grace-harvest) — 최우선

**트리거**: 주기(6h) + 행사 종료 신호
**하는 일**:
1. 갓생북 은혜(Supabase)의 새 기록·사진 감지 → 자비스 로컬 DB(`db/grace/`)로 복사·축적
2. 행사 종료 시 사진 원본 일괄 로컬 이관 → 클라우드 용량 비움 (**무료 티어 유지 장치**)
**존재 이유**: "자비스=두뇌·로컬 DB" 원칙을 실제로 성립시키는 뼈대. 이것이 없으면 데이터는 클라우드에 산다.
**설정**: `config.example.json`의 SUPABASE_URL / SERVICE_KEY (각 교회 자비스 로컬에만 저장 — 저장소에 키 금지)

## W2. 책 마감 (book-finalize)

**트리거**: 행사·시즌 종료
**하는 일**: PDF 책 생성 확인 → 로컬 아카이브 → (선택) 행사 영상 하이라이트 → 책+영상+공유링크
패키지를 리더에게 전달
**존재 이유**: "폐회하니 책이 와 있네" — 체감 효과 최대 지점

## W3. 기록→양육 (record-to-nurture) — 후속 (데이터 쌓인 뒤)

**트리거**: 사람별 기록이 임계 분량 도달
**하는 일**: 로컬 DB 기록을 사람별로 분류·누적("한 사람의 신앙의 책") → 1:1 양육 대화 가이드
초안을 리더에게 제안
**존재 이유**: 축적이 서비스가 되는 지점 — 행사 기록 앱에서 양육 시스템으로

## 구현 순서 (PRD 로드맵)

W1(3주차) → W2(4주차) → W3(후속). 본 v0.1 저장소에는 명세만 실려 있으며,
구현 스크립트는 각 주차에 이 폴더에 추가된다.
